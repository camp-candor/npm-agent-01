### The Short Answer

* **`npm-agent-01` has a Release badge (`Latest`)** because an actual **GitHub Release** was created (via `gh release create`).

### Root Cause Analysis

Both repositories use the same release automation architecture:
1. [`.github/workflows/bump-version.yml`](file:///d:/cauldron-it-com/995.library/.github/workflows/bump-version.yml) bumps the version and pushes the tag using:
   ```yaml
   token: ${{ secrets.GH_TOKEN || secrets.GITHUB_TOKEN }}
   ```
2. [`.github/workflows/release.yml`](file:///d:/cauldron-it-com/995.library/.github/workflows/release.yml) listens for tag pushes (`on: push: tags: ['v*.*.*']`) and runs:
   ```bash
   gh release create "${TAG_NAME}" \
     --title "${TAG_NAME}: Edge DevOps Control Plane & Autonomous Agent Boilerplate" \
     --generate-notes \
     --latest
   ```

#### The Difference: Missing `GH_TOKEN` Secret

By GitHub Actions security design:
> **Pushes made with the default `GITHUB_TOKEN` will never trigger downstream workflows.** This is GitHub's built-in anti-recursion safeguard.

Checking the GitHub Actions configuration for both repositories:

| Repository | Repo Secret `GH_TOKEN` | What Pushed the Tag | Did `release.yml` Trigger? | GitHub Sidebar |
| :--- | :--- | :--- | :--- | :--- |
| **`npm-agent-01`** | **Present** (created Oct 8) | Custom Personal Access Token (`GH_TOKEN`) | **Yes** (`Publish GitHub Release` ran & succeeded) | **Releases 5** (`v0.1.4` `Latest`) |
| **`995.library`** | **Missing** (`secrets: []`) | Default `GITHUB_TOKEN` | **No** (GitHub suppressed the tag push trigger) | **Releases: 2 tags** (`Create a new release`) |

Because `GH_TOKEN` was absent in `camp-candor/995.library`, `bump-version.yml` fell back to `GITHUB_TOKEN`. The tag push succeeded, but GitHub refused to trigger the downstream `Publish GitHub Release` workflow.

### How to Fix `995.library`

#### 1. Add `GH_TOKEN` to `995.library` Repository Secrets
1. Navigate to: `https://github.com/camp-candor/995.library/settings/secrets/actions`
2. Add a **New repository secret**:
   * **Name**: `GH_TOKEN`
   * **Value**: Your Personal Access Token (classic with `repo` + `workflow` scopes, or fine-grained with read/write access to contents and workflows).

*Once added, future runs of `Bump Version & Dispatch Release` will automatically trigger `Publish GitHub Release`.*

#### 2. Create the GitHub Release for Existing Tags
To create the release for the tag already pushed (`v0.1.1`):
* Click **Create a new release** on the GitHub sidebar in `995.library`, choose tag `v0.1.1`, and click **Publish release**; or
